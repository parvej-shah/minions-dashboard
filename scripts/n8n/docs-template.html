Minions Content Pipeline

How an RSS headline becomes a reviewed blog post, a cover image and three social posts. The page covers every workflow, every hand-off between n8n, the dashboard and Supabase, and every prompt the system sends to a model. That includes the n8n content pipeline, the dashboard's onboarding calls, and the text fragments that code injects into those prompts. Everything is copied word for word from the live workflow JSON and the repo.

Picks one idea and claims it with a compare-and-set PATCH to PICKED. Human review Editorial Studio

The editor reads the draft, edits the article and variants, and ticks off flagged claims in the Claims Gate. Clicking Approve marks the asset approved and calls /api/pipeline/publish. Auto-publish exists in code but is off in practice, because require_review defaults to true and the cover is never ready when the draft finishes.

Publish 03_review_publisher

Takes up to 3 approved assets that have no published_at. Each goes to the blog, either through the tenant's webhook or the hosted getminions.ai blog (tenant zero only). It then posts to Facebook as a photo post with the blog link as the first comment, and to LinkedIn as an image post, using each tenant's channel credentials. Finally it stamps the post IDs.

00c_stale_claim_sweeper every 15 min

Resets ideas stuck at PICKED for over 30 minutes with no asset back to HARVESTED, and sends a Telegram alert. Covers crashed draft runs.

00c_pipeline_error_alert error trigger

Sends a Telegram alert for any failed node. It also recovers the run's callback_url and marks the pipeline run FAILED, so the HUD stops spinning.

00b_posting_scheduler_dispatcher paused

Every 5 minutes it would read tenants whose posting schedule is due, create a DRAFT pipeline run, and fire 02. Deactivated on 21 Sep when scheduled drafts were turned off.

01 · Idea harvester

Ykpl0pQTzBdZlDcA · {{NODES:01_idea_harvester}}. Brand context comes from /api/brand/context, which supplies positioning, directives, author standing, tenant RSS sources, the pillar rotation for this run, and fingerprints of the 60 most recent theses. If that context is incomplete (context_complete: false) or has no pillar_rotation, the run fails instead of falling back to generic sources.

  1. Resolve Client ID: takes client_id, callback_url and callback_secret from the webhook body. It starts only from the webhook (dispatcher, dashboard, or 02 when the queue is empty) or a manual run.
  2. Read Ideas: loads up to 2,000 of the tenant's ideas.
  3. Backlog Guard: if more than 12 REFINED ideas are unclaimed, the run skips and reports skipped: true in the callback.
  4. Fetch Brand Context: branches into two parallel paths, A and B.
  5. A · Refine: any NEW rows are sent to the refiner (prompt below) and saved as REFINED with source MANUAL.
  6. B · Expand Tenant Sources → RSS: reads one feed per active source. Without sources it falls back to Hacker News, TechCrunch AI and the n8n blog. Feed health goes to /api/internal/source-status.
  7. Build Harvest Payload: groups signals by source, takes a rotating window of each source's max_items (offset by harvest_run_index), and caps the total at 18.
  8. Qwen Harvest: generates exactly one idea per rotation angle.
  9. Attach Source URLs → Dedupe Ideas: maps signal_index back to the article, then builds a stemmed 8-token thesis fingerprint. An idea is dropped if its fingerprint overlaps a known thesis by Jaccard 0.5 or more. This mirrors src/lib/thesis.ts.
  10. Fetch Source Articles → Craft Notes: /api/ideas/craft fetches the article text, and the model describes only its structure. Merge Craft removes any sentence that contains a run of 9 or more words copied from the source.
  11. Assign IDs → Sync Ideas to DB: assigns global sequential IDEA-0001 IDs, upserts with status REFINED, and reports COMPLETED with harvestedCount.

02 · Idea to asset

0ZeUkMgGXpBKVB2A · {{NODES:02_idea_to_asset}}. The strategist writes the brief, the writer drafts, the editor fact-checks, and the distributor adapts the piece per platform. Brand voice comes from three sources: brand_directives (priority 1–2 and audience-scoped), brand_profile, and up to 5 tone_examples.

  1. Generate run_id: carries idea_id, client_id and the callback details from the dashboard. It starts only from the webhook or a manual run.
  2. Select Target → Claim Idea Row: chooses the idea, then PATCHes it to PICKED only if status, claimed_at and a null draft_asset_id still match. If another run already claimed it, this run does nothing. If there is nothing to draft, it fires the harvester (SCHEDULER_CASCADE_EMPTY_QUEUE).
  3. Read Brand · Brand Profile · Tone Examples · Posting Schedule: loaded in parallel.
  4. Assemble Brand Context: picks the hook archetype deterministically from the pillar. Myth / contrarian / architecture / systems gives INVERSION. Stakes / economics gives DIRECT COST. Anything else gives SCENE-FIRST. Brand context is capped at 8,000 characters, and only PROOF rows with approved: true and an http(s) source are included as verified proof.
  5. Executive Strategist: produces the brief and the cover-card copy.
  6. Need Evidence?: if the idea is evidence_required = Y or the strategist listed evidence_needs, the signals are formatted as SUPPLIED_SOURCE_n leads and each need becomes an UNVERIFIED_NEED_n marker that must not be stated as fact.
  7. Writer: drafts the article. Editor: tightens it and extracts claims.
  8. Parse Claims and Gate: matches each claim against approved proof (at least 3 shared significant words and ≥40% overlap). An unbacked STATISTIC, FACT, MARKET_CLAIM or PRODUCT_CLAIM sets claims_ok = N. An unapproved CUSTOMER_RESULT sets it to BLOCKED.
  9. Variants: writes the LinkedIn, Facebook and X posts. The same node assembles the cover image prompt.
  10. Validate Social Variants: checks for empty variants, X over 280 characters or more than 1 hashtag, LinkedIn over 2 hashtags, the Minions brand appearing in another tenant's copy, and invented client stories.
  11. Prepare Asset Row: runs a word-boundary scan for FORBIDDEN directives, and any hit makes the draft BLOCKED. It assigns a byline (a random founder for tenant zero, otherwise “{Brand} Team”) and sets hero_status: PENDING. Auto-publish requires claims Y, no review, and a permanent hero, so in practice drafts are never auto-published.
  12. Sync Idea (REVIEW) → Sync Asset → Asset Write OK?: any non-2xx response throws, so the error workflow marks the run FAILED. The run then writes claims, sends a Telegram notice, and reports COMPLETED with the assetId, while in parallel Dispatch Hero Generation fires 04.
Hook archetype instructions are injected into the strategist prompt as ${hookArchetype} and ${archetypeInstruction}:
INVERSION: “Contrast a common industry assumption against a practical architectural observation… Never use dramatic or arrogant words like ‘dogma’.”
DIRECT COST: “Open with the concrete, immediate consequence of inaction or bad architecture, stated clearly and objectively.”
SCENE-FIRST: “Open inside a specific, recognizable operational moment the reader has lived, then reveal what is actually happening underneath it.”

04 · Hero image

10vre0a16gvu32Hu · {{NODES:04_hero_image}}. 02 (Parse Variants and Prepare Rows) sends cover_inputs: the strategist's thumbnail_card, the title and the tenant's brand colors. 04 renders the prompt through /api/internal/prompts/cover.

Headline comes from thumbnail_card.headline (3–5 bold words); one word is rendered in brand coral. Kicker is thumbnail_card.subtitle, cut at a word boundary to 90 characters or fewer. Wordmark is the company name, set in top-right ink.
Corner icon: the strategist's physical_scene is used unless it mentions trade hardware on a non-trade account, is shorter than 25 characters, or mentions a “clipboard”. In those cases a keyword router picks a line glyph instead: chat bubble, soundwave, bar chart, node flow or dashboard card for abstract topics, and wrench+droplet, gauge, headset, bolt, roof or magnifier for trade topics.
  1. Read Hero Request → Render Cover Prompt: reads asset_id and cover_inputs, then renders the cover prompt. A pre-rendered image_prompt from an older 02 run skips the render.
  2. Qwen Image 3.0 Pro: size 1280*720, prompt_extend: true, 120s timeout.
  3. Needs Safe Image Retry? → Render Safe Cover Prompt: if no image URL comes back, it retries with the fixed safe prompt and prompt_extend: false.
  4. Upload Hero to R2: calls /api/media/ingest, which downloads the image, converts it with sharp to WebP, and stores it under assets/.
  5. Resolve Hero Outcome: sets READY only when the R2 upload succeeded. An Alibaba URL alone never counts, because it expires in about 24h. A safety refusal (DataInspectionFailed) sets BLOCKED_BY_SAFETY; anything else sets FAILED.
  6. Attach Hero to Asset → Attach OK?: throws on a non-2xx response so a cover that silently never arrives becomes a visible error.

03 · Review publisher

4GNbfvmveKtbJrVd · {{NODES:03_review_publisher}} No model calls. It publishes what a human approved.

  1. Read Approved Assets: claims_ok=Y · status=PUBLISHED · published_at is null, oldest first, 3 at a time. The webhook and the 5-minute cron run the same query.
  2. Filter Approved Assets: puts the hero image at the top of the markdown body if none is embedded, and maps the facebook_variant and linkedin_variant columns.
  3. Resolve Blog Channel: if the tenant set a blog webhook, POSTs the article there. Otherwise, the hosted blogs upsert applies only to tenant-zero-getminions-ai, and every other tenant is tagged “skipped”.
  4. Resolve Facebook Channel: /api/channels/credential?channel=facebook. If it is active and has a token, posts the hero image with fb_variant as the caption to /{page}/photos, then comments with the blog link.
  5. Resolve LinkedIn Channel: downloads the hero, calls images?action=initializeUpload, PUTs the binary, then POSTs to /rest/posts with the image URN and li_variant as commentary.
  6. Merge Publish Results → Mark Asset Published: stamps published_at, published_urls, and the Facebook and LinkedIn post IDs with their timestamps, then sends a Telegram alert.
