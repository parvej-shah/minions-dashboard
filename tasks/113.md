# Task 113: Posts must not open the same way (first-login three, then everywhere)

Status: Phases 1-4 BUILT 2026-11-21 (local, not pushed). Phase 5 (measure, needs OK) and the live check next.
Owner said go without picking: defaults used (no schema change, count-based
rotation; third post = the reader's side).

Phase 1 as built: each role picks the source type whose existing opening no
other post in the set uses (lesson: PROFESSIONAL_OPINION then PAST_EXPERIENCE;
reader: ICP_QUESTION then MARKET_SIGNAL), so `hookFor` needed no special case.
The reader's post drops the memory and trust basis, so it can't retell the
story in the first person and its cover isn't titled as the author's story.

Phase 2 as built: `hookOptions` gives each source type a ranked list; `hookFor(input, turn)`
walks it by the workspace's post count (`asset.count`), so no schema change.
Starter-set ideas keep turn 0, so phase 1's planned openings hold. AUTHOR SCENE
only when the trust basis has LIVED_EXPERIENCE. The strategist gets the last
8 hooks (21 days) as RECENT OPENINGS and must start with a different first word.

Phases 3-4 as built (owner: "keep cost in head"): `lineRepeats` (src/lib/drafts/openingRepeats.ts)
checks the hook against the last 8 hooks and the LinkedIn close against the last 8 closes.
A repeating hook gets the one existing humanize rewrite (hook only), kept only if it no longer
repeats; the LinkedIn post's repeated first line then takes the new hook in code. A repeated
close only rides along in a rewrite the post already gets. Content mode and close kind
(observation / question / next step) rotate by post count as prompt hints; no new call.

## Goal
The three posts a new user gets on first login read as three different posts:
different opening, different focus, different shape. Across the whole system,
a workspace's posts stop opening with the same move week after week.

## Why they look the same today (found in code, 2026-11-21)
1. **Same story three times.** A new workspace has no harvested ideas yet, so
   `pickStarterSet` (src/lib/starterSet.ts) fills both extra slots with
   REFRAMEs: the setup story again, with only a different angle brief attached
   (src/services/starterSet.ts). All three posts get the same raw story and memory.
2. **Same opening style three times.** `hookFor` (src/lib/drafts/strategy.ts)
   decides by source type before angle. The reframes copy the first idea's
   source type, so all three get the same hook archetype (a past-experience
   story always gets AUTHOR SCENE), and the angle never reaches the opening.
3. **The same thing happens system-wide.** One source type always gets one
   archetype: every PAST_EXPERIENCE idea opens AUTHOR SCENE, every
   PROFESSIONAL_OPINION idea opens POSITION, and most other ideas open
   READER SCENE. Nothing rotates.
4. **No memory of openings.** The strategist sees recent *arguments*
   (src/services/draftContext.ts `recentArguments`) but never recent *first
   lines*. The three starter posts are drafted in parallel, so they can't see
   one another either.
5. **The sameness spreads to every channel.** The LinkedIn variant must open
   with the hook "verbatim or lightly sharpened" (src/lib/prompts/variants.ts),
   so one repeated hook repeats on LinkedIn, Facebook, X and Instagram.
6. **The checks cover one post at a time.** src/lib/drafts/slop.ts catches
   patterns inside a single post. Nothing compares a new post with the ones
   before it.

## Plan

### Phase 1: First-login three (the first impression)
- **Three planned roles, not three reframes.** The starter set assigns each
  post a fixed, different job up front:
  1. *The story*: the setup story itself (unchanged), opening AUTHOR SCENE.
  2. *The lesson*: what the story taught, argued as a view, opening POSITION.
     It must not retell the story; the story is evidence, not the opener.
  3. *The reader's side*: the ICP's version of the problem, opening READER
     SCENE or THE QUESTION, with the advice in a how-to shape.
  A harvested idea that passed the gate still takes a slot when one exists, as
  today, and gets the archetype not used by the others.
- **Pass the archetype explicitly.** For STARTER_TAG ideas, choose the hook
  from the planned role, not from source type. This needs no schema change:
  the role lives in the angle brief, and the tag already marks these ideas.
- **Tell each draft about its siblings.** Because all three are planned
  before any is drafted, each strategist call gets the other two roles and
  "don't open on the same moment or the same first words".

### Phase 2: Rotation across the system
- **`hookFor` returns a ranked list** of archetypes that fit the evidence,
  for example:
  - PAST_EXPERIENCE: AUTHOR SCENE, POSITION, INVERSION, THE DECISION
  - USER_NOTE: POSITION, THE QUESTION, READER SCENE
  - Unmatched ideas: READER SCENE, THE QUESTION, DIRECT COST, INVERSION

  It still only offers archetypes the evidence supports; AUTHOR SCENE needs a
  lived story.
- **Pick the first archetype the workspace hasn't used lately.** With no
  schema change, the rotation is deterministic: offset the list by the
  workspace's recent asset count. Cleaner option: store the archetype on the
  asset, which is a prisma change and needs your OK.
- **Recent openings go to the strategist.** Next to "recently posted
  arguments", add the last 8 hooks (the `asset.hook` field), fenced as data:
  "these openings are taken; use a different first word and structure".

### Phase 3: A code check across posts (prompts alone are not enough, as slop.ts already learned)
- New pure function `openingRepeats(newHook, recentHooks)`. It flags a hook
  that matches a recent one on any of these:
  - the same first 3 words
  - the same first word in 3 or more of the last 5 posts
  - trigram overlap above 0.5
  - the same template ("Most people…", "Last week…", "Here's…")
- When it fires, the existing polish path (src/services/draftPolish.ts) gets
  one rewrite of the hook only, and keeps the rewrite only if it no longer
  repeats. This is the same pattern slop.ts uses.

### Phase 4: Beyond the first line
- Rotate **content mode** (INSIGHT, STORY, HOW_TO, CASE_NOTE, OPINION) the same
  way, so the body shape varies too, within `allowedContentModes`.
- Vary the **close**: a question vs a plain observation vs a next step. Check
  it with the same cross-post function, since a repeated closing question is
  as visible as a repeated opening.

### Phase 5: Measure
- A read-only script scores a workspace's last 20 posts on:
  - first-word share
  - opening trigram overlap
  - archetype spread
  - closing repeats

  Run it before and after. It reads the live DB, so the owner OKs each run.
