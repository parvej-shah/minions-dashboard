# Task 98: Custom designs take the theme colours


## Goal
A custom cover design follows the workspace's colour theme. Every text colour,
the cover's background and every background behind text must use the theme
colours (var(--ink), var(--paper), var(--accent), var(--secondary)). Icons,
shapes and lines may keep their own colours. A design that breaks this fails
the check with a plain reason and is not saved.

## Files to touch
- src/lib/covers/custom/themeColours.ts (new) + themeColours.test.ts
- src/lib/covers/custom/check.ts (run the rule before drawing)
- src/lib/covers/custom/contract.ts (instructions say it)
- src/lib/covers/custom/check.test.ts (contrast test no longer relies on a fixed colour)

## Constraints
- Only the check (check + save routes) enforces it. Loading a saved design
  re-parses only, so designs saved before this keep working.
- Gradients pass when every colour in them is a theme colour (or transparent).
- A picture (url()) behind text is allowed: it is the design's own element.

## Acceptance tests
- [x] `npm test`, `npx tsc --noEmit` and lint pass
- [x] fixed text colour (hex, rgb, named) is refused, naming the slot
- [x] text with no colour set anywhere is refused
- [x] fixed cover background, or a missing one, is refused
- [x] a fixed-colour panel behind text is refused; a gradient of theme colours passes
- [x] fixed colours on icons, SVG and shapes not behind text pass
- [x] GOOD_TEMPLATE still passes; the instructions mention the rule
- [x] fixed words ("Book now") follow the same colour rule
- [x] the instructions state every rule the check enforces (tags, style properties, fonts, limits, sizes, colours, pictures) in numbered sections, with a complete example that a test keeps passing
