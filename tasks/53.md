# Task 53: Layout picker tiles show the post's own text

## Goal
Each tile in the Studio's cover "Layouts for this post" picker is the real cover renderer drawing THIS post's headline, subtitle, figure, quote and points in that layout, instead of the shared demo picture. Cost: no AI call, no storage write, no DB write.

## Architecture
- `src/lib/covers/layoutSwitch.ts` (pure): one source of truth for "can this cover be drawn in layout X, and with what copy". Used by BOTH the real layout edit (renderAssetCover) and the preview, so a tile never promises a layout the click would refuse. Also holds the render-attempt order.
- `src/services/coverPreview.ts`: loads the stored cover spec + brand, switches layout, renders the first attempt that fits, shrinks to a 216x270 webp with sharp. Read-only. Small in-process LRU keyed by spec hash.
- `GET /api/assets/[id]/cover/preview?layout=X&v=<hash>`: one tile per request. The browser fetches tiles in parallel (several serverless instances), caches each by URL (`v` changes only when the post's text changes, not when a layout is picked), and tiles appear one by one.
- `ThumbPicker` option gets `liveSrc`: the static sample shows at once; the live tile fades in over it when loaded; on any error the static sample stays.
- Only the visible tiles are requested (4 suggested; the rest after "See all").
