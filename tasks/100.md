# Task 100: Pick your own design in the post editor


## Goal
In the post editor's layout picker, the workspace's saved designs show as
tiles (named, drawn live with the post's own words) in front of the built-in
layouts, and clicking one redraws the cover in that design.

## Files to touch
- src/lib/covers/pickerThumbs.ts + pickerThumbs.test.ts (design tile ids, preview URL, CUSTOM never a built-in tile)
- src/app/api/assets/[id]/cover/route.ts (accepts `design`)
- src/app/api/assets/[id]/cover/preview/route.ts (accepts `design`)
- src/services/cover.ts (an edit can ask for a saved design)
- src/services/coverPreview.ts + coverPreview.test.ts (draws a tile in a saved design)
- src/lib/mappers/asset.ts, src/types/asset.ts (the cover says which design it uses)
- src/hooks/useEditorialDraft.ts (CoverEditInput.design)
- src/components/editorial/CoverImageCard.tsx

## Constraints
- Only an ACTIVE design of the post's own workspace can be picked; anything
  else is refused with a plain reason and nothing is drawn.
- The click runs the same fit rules: a post that does not fit the design gets
  "That doesn't fit your design: …", never a broken cover.
- The tile URL names the design's version, so a new version draws a new tile.
- No new tables, no SQL.

## Acceptance tests
- [x] `npm test`, `npx tsc --noEmit` and lint pass
- [x] design tile ids round-trip; CUSTOM is never offered as a built-in tile
- [x] the current design comes first among the design tiles
- [x] a preview tile draws the post's words in the given design, with the cut-out only when the design uses it
- [x] an edit asking for an archived or unknown design is refused
- [x] the cover DTO carries {id, version} of its design

## Do not touch
- src/constants/nav.ts, .env*, prisma/, n8n/
