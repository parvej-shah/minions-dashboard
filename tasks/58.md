# Task 58: Layout tiles under 100 ms, same quality

## Goal
Every layout picker tile is drawn by the server in under 100 ms, at the same quality as the real cover.

## Measured (local, warm, one thread)
- satori layout: 19-59 ms for every layout. The real cost was rasterizing the full 1080x1350 cover
  (66-2382 ms; blur/shadow filters and the nested background SVGs) and then shrinking it.
- Rasterizing at tile size with sharp still took 25-150 ms (Neon, Tagged, List over 100); resvg was slower.
- So the tile is sent as the satori SVG itself (13-26 KB gzipped) and the browser draws it: same
  vector, same fonts (glyphs are paths), sharp at any screen density.

## Files to touch
- package.json: satori pinned to 0.25.0, the version next/og bundles, so tiles match the real cover
- src/lib/covers/render.ts: `renderCoverSvg`, `needsFallbackGlyphs`
- src/services/coverPreview.ts: SVG tile; headshot/cut-out shrunk for tiles; webp fallback for text our fonts lack
- src/app/api/assets/[id]/cover/preview/route.ts: content type, CSP + nosniff for SVG
- tests: src/services/coverPreview.test.ts, src/lib/covers/render.test.ts

## Constraints
- Nothing stored in R2. Real covers keep the PNG path unchanged.
- Text our fonts lack (next/og fetches fallback glyphs) keeps the old webp path, so no tile drops letters.
- SVG response: `Content-Security-Policy: default-src 'none'; img-src data:; style-src 'unsafe-inline'`, nosniff.

## Acceptance tests
- [x] renderCoverSvg returns an SVG of the cover size for a real spec, under 100 ms warm for every layout
- [x] a Latin tile is image/svg+xml, carries the post's words' layout, no upload/no row write
- [x] text outside our fonts falls back to a 216x270 webp
- [x] an embedded headshot is shrunk for the tile
- [x] `npm test` (mine), tsc, lint, `next build`

## Do not touch

## Result (2026-11-12)
- Satori per layout, warm, alone (`COVER_BENCH=1`): 15-38 ms. Before: 125-2176 ms per tile.
- Local browser check (dev server, real post): tiles are image/svg+xml and render correctly.
  Server time per tile ~140 ms locally, nearly all one DB round trip from Dhaka; the duplicate
  ownership query was dropped and the asset + brand reads now run together.
- Not changed: the ~300 ms auth check every API route pays; the real cover's PNG render.
