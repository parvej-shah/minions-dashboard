# Task 19: Unpublish a post from LinkedIn in the Studio

## Goal
A published post that Minions sent to LinkedIn can be unpublished from Editorial Studio:
the LinkedIn post is deleted through LinkedIn's API, the post comes off the blog too, and
the draft returns to the review queue with its content kept. Supersedes the 2026-10-24 decision.

## Files to touch
- src/lib/linkedin.ts (deleteLinkedInPost)
- src/services/linkedinUnpublish.ts (+ .test.ts)
- src/app/api/assets/[id]/unpublish-linkedin/route.ts
- src/lib/mappers/asset.ts, src/types/asset.ts (linkedin_removable)
- src/hooks/useEditorialDraft.ts, src/components/editorial/ReviewDock.tsx, EditorialStudio.tsx
- docs/decisions/DECISIONS.md

## Constraints
- DELETE https://api.linkedin.com/rest/posts/{urn} with the workspace's own LinkedIn token
  (w_member_social). 404/410 from LinkedIn = already gone, still succeed.
- Only when Minions holds the LinkedIn post id. A hand-posted post has none: refuse with a
  clear message (delete it on LinkedIn).
- Refuse when the post also went to Facebook (re-approving would post there twice).
- The asset never stays PUBLISHED with an empty publishedAt (the publisher's poll would re-send it).
- On LinkedIn failure nothing changes in Minions.
