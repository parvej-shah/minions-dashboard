# Task 101: Cover font fallback


## Goal
When the post's words don't fit a layout in the workspace's cover font, the
cover is drawn in the default font (Bricolage) instead of failing or losing
words, so switching layouts works whatever font the brand picked.

## Files to touch
- src/lib/covers/layoutSwitch.ts + layoutSwitch.test.ts (attempts try the default font)
- src/services/cover.ts (a note when the default font was used)

## Constraints
- Order: keep the words first, then the brand's font, then the illustration.
  For each copy: brand font with art, brand font without art, default font
  with art, default font without art; only then shorter copy.
- Custom designs bring their own fonts: no fallback for CUSTOM.
- The stored cover records the font it was drawn in.

## Acceptance tests
- [x] `npm test`, `npx tsc --noEmit` and lint pass
- [x] attempts try the default font after the brand font, before shorter copy
- [x] no extra attempts when the font is already the default, or for CUSTOM
- [x] the live tiles and a reviewer's layout switch follow the same order (both use editAttempts)

## Do not touch
- src/constants/nav.ts, .env*, prisma/, n8n/
