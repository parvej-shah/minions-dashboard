# Task 99: Photo and cut-out in custom designs


## Goal
Someone (or their agent) designing a cover knows exactly what the headshot and
the cut-out are and how to place them, the check refuses a picture that would
be stretched, and the preview shows the workspace's own photo and cut-out (or
a shaped stand-in when it has none) instead of a grey box.

## Files to touch
- src/lib/covers/custom/pictures.ts (new) + pictures.test.ts
- src/lib/covers/custom/check.ts (rule + pictures in the previews)
- src/lib/covers/custom/contract.ts (section 5 + example with a cut-out)
- src/lib/covers/custom/fixtures.ts (photo gets object-fit)
- src/lib/covers/custom/check.test.ts
- src/services/coverTemplates.ts (loads the workspace's pictures for the check)
- src/services/coverPreview.ts (export the shrink helper)
- src/components/brand/YourDesignsCard.tsx (one line when stand-ins are drawn)

## Constraints
- Only the check enforces object-fit, so designs saved earlier still load.
- The real pictures are read only for the check (no writes), only when the
  design uses them, and shrunk before drawing. The saved thumbnail keeps the
  stand-ins, so no headshot is stored in the design row.
- Stand-ins are neutral figures with the real shapes: a portrait cut-out on a
  transparent background and a square headshot.

## Acceptance tests
- [x] `npm test`, `npx tsc --noEmit` and lint pass
- [x] a {{cutout}} <img> without object-fit:contain is refused with a plain reason
- [x] a {{photo}} <img> without object-fit:cover or contain is refused
- [x] inline data: pictures are not affected

- [x] without the workspace's pictures the previews draw stand-ins and say which slots were stood in for
- [x] the instructions say what each picture is, its shape, object-fit, anchoring, text off the person, and that the design must work without them; the example uses a cut-out and still passes
