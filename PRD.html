Minions.AI Agent Cockpit

Complete build guide for migrating from Google Sheets + Google Docs to a Next.js + Supabase dashboard. Written for an AI developer agent. Follow this document exactly — every requirement, schema, and UX decision is final unless annotated with DISCUSS.


Next.js 14 App Router Supabase + Prisma Cloudinary Google OAuth minions.getminions.ai

Product Vision

Minions.AI is an Autonomous Marketing Operations Cockpit for a US home-services business (HVAC, Plumbing, Pest Control). Three AI agents run continuously in n8n — harvesting content ideas, converting them to long-form assets with AI-generated cover images, and publishing them to Blog, LinkedIn, and Facebook.

Today, the entire operation is glued together with Google Sheets (data) and Google Docs (drafts). This is fragile, unscalable, and impossible to review professionally. This dashboard replaces both, and becomes the single source of truth for every agent action.

🎯

The marketing manager's job in one sentence: Open the dashboard, see what the agents did overnight, review and approve one pending draft, and close the tab — with confidence that publishing is handled.

Every design decision must serve this loop. Zero spreadsheets. Zero Docs. Zero cognitive load.

The three n8n workflows this dashboard orchestrates

01 — Idea Harvester

Polls Google Trends, Reddit trade forums, TechCrunch. Writes new ideas to Supabase ideas table. Runs on a schedule.

02 — Idea to Asset

Claims a ready idea, reads brand context from Supabase, calls Qwen AI to generate a 5-stage article + cover image. Writes draft to assets table.

03 — Review Publisher

Triggered by the dashboard when manager approves a draft. Publishes to Blog/LinkedIn/Facebook. Writes published URLs back to Supabase.

Problem Statement

The current Google Sheets + Docs setup fails the marketing manager in four specific ways. Every requirement below is a direct fix to one of these failures.

Pain PointRoot CauseFix in This Dashboard
Unpredictable fields → bugs Google Sheets columns drift; formulas break; agents write to wrong columns Strict Prisma schema. All writes go through typed API routes. Schema migrations are versioned.
No review UX Reviewing a draft in Google Docs requires opening 3 tabs, copy-pasting, and manually updating a Sheet cell One-screen Editorial Studio: read the draft, see the cover image, approve/reject with one button
No published post tracking After publish, there's no record of where the post went or what it looks like live Dedicated Published Posts page. Every post stores platform + URL + thumbnail + publish date
Brand context is a hidden Sheet tab Agents read a flat sheet; no way to upload logo, set colors, or manage thumbnail templates visually Brand & Directives page with visual logo upload, color swatches, Cloudinary-backed asset management

Tech Stack — Mandatory, No Substitutions

Frontend + API

Next.js 14 with App Router. Use Server Components wherever possible. API routes in app/api/. No Pages Router. No separate Express server.

Database

Supabase (hosted PostgreSQL). ORM: Prisma with migrations. The Supabase client is used for realtime subscriptions only. All other DB access goes through Prisma.

Auth

NextAuth.js v5 with Google OAuth provider. Whitelist: only xpeedlab@gmail.com can log in. All routes except /api/webhooks/* require an active session.

Image Storage

Cloudinary account: parvejshahlabib07@gmail.com. All cover images, logos, and brand assets go to Cloudinary. Store the Cloudinary URL in Supabase.

Deployment

Vercel. Domain: minions.getminions.ai. Use Vercel environment variables for all secrets. Enable edge runtime on webhook routes for low latency.

Styling

Tailwind CSS v3 with a custom design tokens config (see Design Tokens section). shadcn/ui for base components. No Material UI. No Chakra.

⚠️

Do not use Prisma Accelerate or Prisma Data Platform. Connect directly to the Supabase PostgreSQL connection string. Use connection pooling via Supabase's built-in PgBouncer (port 6543, not 5432) in production.

Auth & Security

Google OAuth Setup

  • 1
    Create a Google Cloud project at console.cloud.google.com. Use the Google account xpeedlab@gmail.com.
  • 2
    Enable the Google OAuth 2.0 API. Create credentials → Web Application. Authorized redirect URI: https://minions.getminions.ai/api/auth/callback/google and http://localhost:3000/api/auth/callback/google for dev.
  • 3
    Store GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET in Vercel environment variables. Never hardcode.
  • 4
    In NextAuth config, add a signIn callback that rejects any email not in the allowlist: ['xpeedlab@gmail.com']. Return false for any other email — this prevents unauthorized access even if someone knows the OAuth URL.

Webhook Security

The /api/webhooks/* routes are called by n8n, not by a browser. They use a shared secret header instead of OAuth:

// Every webhook route must verify:
const secret = req.headers['x-webhook-secret'];
if (secret !== process.env.WEBHOOK_SECRET) {
  return Response.json({ error: 'Unauthorized' }, { status: 401 });
}

Set WEBHOOK_SECRET to a random 32-character string in Vercel. Set the same value in each n8n workflow's HTTP Request node headers.

Database Schema (Prisma)

This is the complete schema. Run npx prisma migrate dev to apply. Every table has an id UUID primary key and audit timestamps.

// schema.prisma

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")  // Supabase pooler URL (port 6543)
}

// ── 1. IDEAS ─────────────────────────────────────────────
model Idea {
  id          String      @id @default(uuid())
  ideaId      String      @unique  // e.g. IDEA-0004 (human-readable)
  title       String
  excerpt     String?
  trade       String      // HVAC | Plumbing | Electrical | Roofing etc.
  audience    Audience    // ICP | PEER | BRIDGE
  source      IdeaSource  // GOOGLE_TRENDS | REDDIT | HACKER_NEWS | TRADE_NEWS
  tags        String[]
  status      IdeaStatus  @default(HARVESTED)
  ingestedAt  DateTime    @default(now())
  claimedAt   DateTime?
  updatedAt   DateTime    @updatedAt

  asset       Asset?
}

enum IdeaStatus  { HARVESTED CLAIMED DRAFTED PUBLISHED REJECTED }
enum Audience    { ICP PEER BRIDGE }
enum IdeaSource  { GOOGLE_TRENDS REDDIT HACKER_NEWS TRADE_NEWS MANUAL }

// ── 2. ASSETS (Drafts) ───────────────────────────────────
model Asset {
  id              String       @id @default(uuid())
  assetId         String       @unique  // e.g. ASSET-0003
  ideaId          String       @unique
  idea            Idea         @relation(fields: [ideaId], references: [id])

  title           String
  content         String       @db.Text  // full article markdown
  contentHtml     String?      @db.Text  // rendered HTML for preview
  socialVariants  Json         // { linkedin: "...", facebook: "...", twitter: "..." }
  coverImageUrl   String?      // Cloudinary URL
  coverImageCost  Float?       // USD cost to generate cover image
  audience        Audience
  version         Int          @default(1)

  status          AssetStatus  @default(DRAFTING)
  claimsVerified  Boolean      @default(false)
  reviewNotes     String?      // manager's internal notes on rejection

  tokensInput     Int?
  tokensOutput    Int?
  llmModel        String?
  llmCostUsd      Float?
  totalCostUsd    Float?
  latencyMs       Int?

  createdAt       DateTime     @default(now())
  updatedAt       DateTime     @updatedAt

  publishedPosts  PublishedPost[]
  costLedger      CostLedger?
}

enum AssetStatus {
  DRAFTING
  PENDING_REVIEW
  APPROVED
  PUBLISHING
  PUBLISHED
  REJECTED
}

// ── 3. PUBLISHED POSTS ───────────────────────────────────
model PublishedPost {
  id           String     @id @default(uuid())
  assetId      String
  asset        Asset      @relation(fields: [assetId], references: [id])

  platform     Platform
  url          String
  thumbnailUrl String?    // Cloudinary or OG image URL
  publishedAt  DateTime   @default(now())

  // Optional engagement (populated later via platform APIs)
  likes        Int?
  comments     Int?
  shares       Int?
  views        Int?
}

enum Platform { BLOG FACEBOOK LINKEDIN TWITTER INSTAGRAM }

// ── 4. BRAND DIRECTIVES ──────────────────────────────────
model BrandDirective {
  id        String             @id @default(uuid())
  category  DirectiveCategory
  key       String
  value     String             @db.Text
  priority  Int                @default(1)
  scope     String             @default("ALL")
  active    Boolean            @default(true)
  createdAt DateTime           @default(now())
  updatedAt DateTime           @updatedAt
}

enum DirectiveCategory {
  IDENTITY FORBIDDEN TONE VOCABULARY STYLE FORMAT
}

// ── 5. BRAND ASSETS (Logo, favicon, cover templates) ─────
model BrandAsset {
  id          String          @id @default(uuid())
  type        BrandAssetType
  variantName String          // "primary_logo" | "favicon" | "og_template_1"
  url         String          // Cloudinary URL
  publicId    String          // Cloudinary public_id for transformations
  width       Int?
  height      Int?
  active      Boolean         @default(true)
  createdAt   DateTime        @default(now())
}

enum BrandAssetType {
  LOGO FAVICON COVER_TEMPLATE OG_IMAGE SOCIAL_BANNER
}

// ── 6. AGENTS ────────────────────────────────────────────
model Agent {
  id              String        @id @default(uuid())
  name            String
  role            AgentRole
  model           String        // qwen3.7-max | qwen-plus | qwen3.7-flash | etc.
  systemPrompt    String        @db.Text
  status          AgentStatus   @default(ACTIVE)
  receivesWebhook Boolean       @default(true)
  description     String?
  updatedAt       DateTime      @updatedAt
}

enum AgentRole {
  MARKETING_STRATEGIST CONTENT_WRITER EDITORIAL_REVIEWER
  VISUAL_ART_DIRECTOR VOICE_DISPATCHER SALES_OUTREACH
  BACKOFFICE_OPS RESEARCH_ANALYST
}
enum AgentStatus { ACTIVE IDLE PAUSED }

// ── 7. COST LEDGER ───────────────────────────────────────
model CostLedger {
  id           String   @id @default(uuid())
  assetId      String   @unique
  asset        Asset    @relation(fields: [assetId], references: [id])

  tokensInput  Int
  tokensOutput Int
  llmModel     String
  llmCostUsd   Float
  imageEngine  String?  // qwen-image-3.0
  imageCostUsd Float?
  totalCostUsd Float
  latencyMs    Int
  createdAt    DateTime @default(now())
}

// ── 8. USERS ─────────────────────────────────────────────
model User {
  id        String   @id @default(uuid())
  email     String   @unique
  name      String?
  avatar    String?
  role      UserRole @default(ADMIN)
  lastLogin DateTime?
  createdAt DateTime @default(now())
}

enum UserRole { ADMIN REVIEWER }

n8n Webhook API Specification

All n8n workflows must be updated to POST to these endpoints instead of writing to Google Sheets. All requests must include the header x-webhook-secret: ${WEBHOOK_SECRET}.

EndpointCalled byAction
POST /api/webhooks/idea-harvested Workflow 01 Creates a new Idea record with status HARVESTED
POST /api/webhooks/asset-ready Workflow 02 Creates or updates an Asset record with status PENDING_REVIEW, attaches Cloudinary cover URL, writes cost ledger
POST /api/webhooks/published Workflow 03 Creates PublishedPost records for each platform, updates Asset status to PUBLISHED
POST /api/webhooks/claim-idea Dashboard → n8n Outbound: Dashboard calls n8n webhook URL to trigger Workflow 02 on a specific idea
POST /api/webhooks/trigger-publish Dashboard → n8n Outbound: Dashboard calls n8n webhook URL to trigger Workflow 03 after manager approves

Visuals & Assets Tab — THE MISSING FEATURE

This tab does not exist in the current system. It is required for the AI image generation workflow.

Logo Upload

Drag-and-drop or click to upload. Accepts PNG, SVG, WebP. Uploads to Cloudinary via POST /api/brand/assets. Saves as type LOGO, variant primary_logo. The Cloudinary URL is then passed to n8n Workflow 02 so the Visual Art Director agent can use it in cover image generation.

This is the field the current Brand page is missing. Without it, the AI generates covers without the brand logo.

Favicon

Upload a square image (min 512×512). Show a live preview at 16×16, 32×32, 64×64 sizes. Save as type FAVICON. Also update the Next.js app's favicon — either by writing to /public/favicon.ico or using a dynamic favicon route at /favicon.ico that serves the Cloudinary URL.

Cover Image Templates

Upload reference images that define the visual style for AI-generated covers. Each template has a name (e.g., "Studio Leather", "Dark Tech"), thumbnail preview, and active toggle. The active template's Cloudinary URL is passed to the image generation agent as a style reference.

Brand Colors

Visual color swatches for Primary, Secondary, Accent, Background. Color picker input. Stored as directives with category STYLE. These are passed to the AI agent so cover images match brand colors.

UX Rules — Non-Negotiable

These rules define the quality bar. Violating any of them is a bug, not a design opinion.

  1. 1
    No tables on status pages. Mission Control, Idea Stream, and Published Posts use card grids. Only the Cost Ledger table is permitted because it is an audit log. Everywhere else: cards.
  2. 2
    Every status change is immediate and visible. When an asset is approved, the status badge changes to PUBLISHING in real time (Supabase realtime). The manager must not need to refresh the page to see the result.
  3. 3
    Every published post has a live link. If the webhook sends a URL, it is displayed. If no URL is present, the card shows a warning badge "Link not received" — not an empty field.
  4. 4
